# AI crawlers and robots.txt tokens

Read this when a user asks which AI crawlers Seekwide knows, what blocking one does, or where a row comes from. The same data, in `server/data/ai-bots.json`, drives the ai module; a test checks that every row of it is on this page with its date.

Every row says only what the vendor's own page states, read on the date in its last column; the whole set was last verified on **2026-11-14**. The pages are re-read at every release and at least once a month. A row whose page could not be read is marked "not verified", is shown in the report, and is used by no counted or scored check. Nothing here is fetched during an audit: no request goes to any AI vendor, and Seekwide never pretends to be one of these crawlers.

**Counted** marks the AI search crawlers whose vendor documents what a block does; the report counts how many of them robots.txt lets read the start page. Roles: AI search builds an index for AI answers; Search and AI features is a search engine crawler whose index also feeds AI features; Training collects content for model training; a Training control is a robots.txt token that only states a preference; a fetcher for a user opens a page when a person asks an AI product; the shared preference token `__usage_ai-training` states a training preference that `User-agent: *` never stands for.

The robots.txt column keeps to the vendor's words: "follows robots.txt" only where the vendor says the crawler follows, respects or obeys it; "documents a robots.txt setting" where the vendor says what a disallow does, or that its robots.txt tags manage the crawler, without saying more; "may not apply" and "generally ignores" where the vendor says so.

Not listed: ByteDance's Bytespider, for which ByteDance publishes no page. Matching follows RFC 9309: a token matches case-insensitively and exactly, groups of one token are merged, and `*` applies only when no group names the crawler (or its fallback, for Applebot). What a CDN or firewall does to the real crawler cannot be seen from robots.txt and is not tested; server logs show it.
